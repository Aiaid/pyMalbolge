# 原始 Malbolge：机器模型与参考实现行为

> [English](malbolge-reference.md) | **中文**
>
> 现行参考指南；资料与实现核对日期：2026-10-27。
> 范围：固定字宽 **10 trit** 的原始语言，不是 Malbolge20 或
> Malbolge Unshackled 的规格。

Ben Olmstead 于 1998 年提出 Malbolge，并明确以难以编程为设计目标。
其规格描述一台小型三进制机器，而非操作码与操作数相互独立的普通汇编语言。
一个位置执行什么操作，同时取决于保存的字符、地址和此前对内存的修改。
原始规格与解释器均明确声明置于公有领域。[1][2]

## 1. 哪份资料说明哪种行为？

1998 年的文字规格与 C 解释器存在可观察的差异。本指南采用解释器的输入输出
指令映射，与 Lou Scheffer 的编程分析保持一致，同时单独标明实现缺陷。
若将旧 C 程序的所有行为都视为语言定义，还会把数组越界等未定义行为混入其中。
[1][2][3]

| 证据 | 适合核对的内容 | 限定 |
|---|---|---|
| Olmstead 的规格保存副本 [1] | 机器模型、预期源码限制、操作 | `<` 与 `/` 的输入输出方向和解释器相反 |
| Olmstead 的 C 解释器保存副本 [2] | 解码、赋值、加密、递增的具体顺序 | 包含加载与执行缺陷，部分结果受宿主 C 环境影响 |
| Scheffer 本人的分析 [3] | 编程技巧、跳转与加密的关系 | 扩展提案与非形式化完备性讨论须和原始机器区分 |
| Esolangs 条目 [4] | 社区说明与链接 | 二手总结，不能证明所有实现行为相同 |
| 本仓库源码 [5] | 当前项目 API 行为 | 项目选择不会追溯性地修复原始规格 |

本指南不判定第一个程序、第一个成功算法或早期演示精确日期等历史优先权。
这些说法应分别核对当事人的原始记录或程序。

## 2. 状态与记号

**Trit（三进制位）**有 0、1、2 三种取值。一个机器字包含十个 trit，表示
`0` 至 `3^10 - 1 = 59048` 的无符号整数。内存恰有 `3^10 = 59049` 个单元，
地址为 0 至 59048，代码与数据共用这一个数组。这里的内存单位是机器字，
不能直接当成 59,049 个八位字节。[1]

三个寄存器均占一个机器字，初值均为零：

| 寄存器 | 用途 |
|---|---|
| `A` | 累加器，用于输入、输出与数据运算结果 |
| `C` | 待取指令的地址 |
| `D` | 数据操作使用的地址 |

下文用 `M[x]` 表示地址 `x` 中的字。应区分数值和存放数值的单元：
`D = M[D]` 修改指针，`M[D] = value` 修改内存。语言没有直接把任意字面常量
赋给 `A` 或某个内存单元的指令。[1][2]

## 3. 加载与初始内存

先忽略空白，再为剩余字符分配位置，从地址零开始逐个存入内存。
按预期源码规则，每个字符必须属于图形 ASCII 范围 33–126，且在所在地址解码
为八种允许操作之一。因此，运行时可能出现的其他 NOP，不能随意用作初始源码。
源码最多占 59,049 个单元。[1][2]

当源码至少包含两个字符时，剩余单元按地址递增顺序填充：

```text
M[i] = crazy(M[i-1], M[i-2])
```

这里的 `crazy(x, y)` 将 `x` 用作下方表格的列操作数，`y` 用作行操作数，
顺序不能颠倒。填充是确定性的，既不是随机数，也不是全零；新生成的单元
会立即参与后续填充。[1][2]

原始递推没有为空源码或单字符源码提供明确种子。C 程序在这些情况下读取分配
数组之前的位置，因而不能给出可移植定义。单字符停机程序可能在某台机器上
看似正常，但填充发生在执行之前。[2]

旧 C 加载器只在范围检查内部验证图形字符，其他非空白字节可能未经指令验证
直接进入内存。这是加载器缺陷，不是预期的源码字符集。Scheffer 明确讨论过
在早期复制程序中利用此行为。[2][3]

## 4. 解码与指令

若 `M[C]` 是图形字符，定义：

```text
r = (M[C] + C) mod 94
```

它等价于原解释器先计算 `xlat1[(M[C] - 33 + C) mod 94]`，再按所得操作字母
分派。下表的字母是解码后的助记符；把该字母原样写入文件，通常不会编码出
同一操作。[1][2]

| `r` | 助记符 | 加密与指针递增之前的效果 |
|---:|:---:|---|
| 4 | `i` | `C = M[D]` |
| 5 | `<` | 在八位字节宿主上输出 `A` 的低八位 |
| 23 | `/` | 读入一个字节至 `A`；EOF 时令 `A = 59048` |
| 39 | `*` | `A = M[D] = rotate(M[D])` |
| 40 | `j` | `D = M[D]` |
| 62 | `p` | `A = M[D] = crazy(A, M[D])` |
| 68 | `o` | 不做操作 |
| 81 | `v` | 立即停机 |

执行时，其他余数也作为 NOP，但源码只允许余数 68 对应的 NOP。地址零处允许的
八个图形字符是 `' ( > D Q b c u`，依次对应余数
39、40、62、68、81、4、5、23。将字符移动一格，会让解码余数改变一；
源码位置按去除空白后的序列计算。[2]

输入输出两行遵循 **C 解释器**，不是文字规格中颠倒的说明。输入 EOF 的值为
十个 trit 全二，即三进制 `2222222222`，而不是零或负数机器字。EOF 本身不会
停机。在八位字节宿主上，输出这个值会得到字节 168，因为
`59048 mod 256 = 168`。原 C 程序使用标准输入输出与文本流；平台的换行转换
属于宿主环境行为。[1][2]

## 5. 数据运算

右旋将最低 trit 移至最高位置，保持字宽不变：

```text
rotate(x) = floor(x / 3) + 19683 * (x mod 3)
```

例如十 trit 的 `0000000001` 变成 `1000000000`，即十进制 19683。
旋转十次会还原一个十 trit 机器字。[1][2]

Crazy 运算在十个位置上分别应用以下查表规则：

| 第二操作数 `y` 的 trit / 第一操作数 `x` 的 trit | 0 | 1 | 2 |
|---:|---:|---:|---:|
| 0 | 1 | 0 | 0 |
| 1 | 1 | 0 | 2 |
| 2 | 2 | 2 | 1 |

对于 `crazy(A, M[D])`，行来自 `M[D]` 的 trit，列来自 `A` 的 trit。
各 trit 之间没有进位。该函数不满足交换律：十 trit 下，
`crazy(0, 1) = 29524`，而 `crazy(1, 0) = 29523`。
前导零同样参与运算，因此很小的十进制输入也可能产生较大的结果。[1][2]

## 6. 执行周期与自修改

以下顺序会影响可观察行为：[2][3]

1. 从 `C` 取字并解码。
2. 执行操作；停机指令立即返回。
3. 用加密表转换**此时** `C` 指向的字。
4. `C`、`D` 各自递增，59048 之后回到零。
5. 获取下一条指令。

加密表是图形 ASCII 的固定置换，索引为当前字减 33；它和依赖地址的解码表
是两张不同的表。按输入字符 `!` 至 `~` 的顺序，94 个输出字符为：

```text
5z]&gqtyfr$(we4{WP)H-Zn,[%\3dL+Q;>U!pJS72FhOA1CB6v^=I_0/8|jsb9m<.TVac`uY*MK'X~xDl}REokN:#?G"i@
```

所以再次进入同一地址时，执行的操作可能已经变化。若 `D` 指向代码区，数据
运算也会改写代码。原规格笼统地说内存写入结果会进入 `A`，不能将此扩展为
自动指令加密也会更新 `A`：C 解释器没有把加密结果复制给 `A`。[1][2]

跳转在第 2 步就改变 `C`，因此第 3 步加密的是赋值后的地址，下一次取指则在
该地址后一格，并按 59049 回绕。例如赋值 `C = 100` 后加密 `M[100]`，然后在
101 取指。原跳转单元不会仅因被取出执行就自动受到加密；地址别名仍可能使
这些位置重合。同理，`D = M[D]` 后递增的是新赋值的 `D`。[2][3]

原 C 程序还有两项缺陷，不能不加说明地混进规范化伪代码：

- 若取出的字不在 33–126，执行 `continue`，不改变寄存器或内存，解释器因此
  空转；文字规格则要求结束执行。
- 操作后的加密查表没有范围保护。跳转或数据写入可能让索引越界，产生 C 的
  未定义行为，而不是可移植的新指令或必然停机。[1][2]

## 7. 计算能力的边界

原始机器的内部存储总量固定。对定义良好的机器状态，内存与三个寄存器至多有
`59049^(59049 + 3)` 种组合。这个直接计数只涉及内部状态，不把无限宿主日志、
输出缓冲区或外部输入流算进机器内存。没有后续输入时，内部状态重复就会重复
未来行为。此界限说明原始固定内存机器不是具有无界读写带的通用图灵机，
但并不妨碍长时间计算、循环或有用的算法。[1][3]

仅凭可任意循环，不能说明机器比线性有界自动机更强；线性有界自动机也能循环。
讨论图灵完备性时，必须明确无界存储来自哪里。Scheffer 的 Malbolge-T 修改外部
I/O 模型，Malbolge20 增大有限字宽与地址宽度，Malbolge Unshackled 修改存储
模型。这些是不同语言或提案，不能用来证明原始 Malbolge 有无界内存。[3][4]

## 8. 本项目的接口

以下是实现细节，不是新增的语言规则。[5]

```bash
uv run python -m malbolge examples/hello.mal
uv run python -m malbolge debug examples/hello.mal
```

`malbolge.run(source, input_data=b"", max_steps=..., max_output=...)` 以字节
输出执行原始语言，默认使用 EOF 哨兵，`RunResult` 记录停止原因。
非法取指以 `invalid_instruction` 停止；范围保护会跳过非法加密输入。
这避免了旧 C 的空转与越界查表，而不是重现其受宿主影响的后果。

`run()` 使用 `parse_source`，只去除空格、LF、CR 与 tab，比 C 的 `isspace`
范围更窄。其验证检查解码余数，没有额外施加图形 ASCII 范围限制。
`DenseMemory.initialize_source` 保留前两个种子位置，缺失种子补零，再从
`max(source_length, 2)` 开始填充。这些选择属于本实现，不是原文对短源码的规定。

旧接口 `eval()` 返回字符串，默认 `eof="stop"`，提供的输入耗尽时就返回。
若希望程序观察 EOF，应使用 `eof="sentinel"`。旧初始化仅跳过空格与 LF，
并在短源码上与 `run()` 的初始化器有差异。旧字符串输入使用字符码点；
`run()` 接受字节，并将文本输入编码为 UTF-8。比较字节级行为时不可混用这些
接口。

本仓库的 Python 编译器目标是 **Malbolge20**。编译所得 `.mb` 文件不会自动成为
原始 Malbolge 程序，文件后缀不表示字宽。可选 native VM 与 JIT 同样属于
Malbolge20 功能，均不改变上文描述的原始机器。
